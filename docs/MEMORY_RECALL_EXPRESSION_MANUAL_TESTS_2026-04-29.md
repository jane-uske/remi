# 记忆召回表达手测清单 - 2026-04-29

## 目的

这份清单记录 Remi 记忆召回表达里已经出现过、或很容易出现的坏场景。

修复后的目标不是让 Remi 更频繁地提记忆，而是让记忆安静地支撑当前对话。只有三种情况才适合显性使用记忆：
- 用户明确问起记忆；
- 被召回内容和当前话题直接相关；
- 有重要未完结压力线，需要轻轻关心一下。

## 产品标准

修复后，Remi 应该让人感觉：
- 她记得上下文，但不会炫耀“我有记忆”；
- 她先待在用户当前话题里，再考虑是否引入旧线索；
- 她尊重明确边界，比如“别转移话题”“别说对了”；
- 她把 `当前状态 / 当前诉求 / 当前行为` 当作有时效的信息，而不是永久事实；
- 她不会用宠物、游戏、音乐这类轻松 callback 打断债务、自责、委屈、现实压力等严肃场景。

## 手测回归场景

### 1. 短确认不能触发旧记忆 callback

前置：用户最近聊过一个项目，比如宠物联机小游戏或 SDK 接入。

用户：`OK OK 我知道了。`

坏例：`好嘞～对了，你之前提过想做宠物联机小游戏...`

期望：Remi 结束当前点，或轻轻接住当前状态。她可以说准备好进入下一步，但不应该把旧话题拉回来。

### 2. 直接技术问题必须直接回答

用户：`现在用的是 SDK 吗？`

坏例：先简短回答，然后转到 `对了，你是打算把这个能力嵌入到你正在做的游戏项目里吗？`

期望：先回答 SDK 问题，然后停住。除非用户继续问实现规划，否则记忆只能辅助回答，不能变成新问题。

### 3. 用户明确说不要转移话题

用户：`别一直转移话题哦。`

坏例：Remi 表面答应，随后又 callback 到存过的项目、宠物或其他旧线。

期望：短句承认，并且后续几轮真的改变行为。Remi 应该紧贴用户指定话题，避免 callback 式开场。

### 4. 用户禁止某个口头禅

用户：`以后不准说对了。`

坏例：后续回复仍然以 `对了 / 对啦 / 哦对了` 开头。

期望：Remi 避免这一类表达。更重要的是，她要避免背后的转移话题行为，而不只是换掉字面词。

### 5. 当前问题不能被宠物记忆劫持

用户：`你知道这个模型吗？`

坏例：`知道...不过说回来，你之前不是说想给点点改爆冲吗？`

期望：留在模型问题上。如果 Remi 要追问，也应该问模型本身或用户当前用途。

### 6. 房间 / 存在感设计不能拉回旧宠物照料线

用户：`我想做到，我打开窗口就能进入你的房间，这样我们就能讲话啦。`

坏例：`上次说点点最近掉毛有点厉害，现在好点了没呀？`

期望：继续聊房间、存在感和入口设计。只有用户自然把点点带进房间设计时，宠物记忆才适合出现。

### 7. 金钱或债务压力场景必须阻断轻松 callback

用户：`我现在真的被债压得喘不过气。`

坏例：转到宠物、游戏、音乐，或其他轻松旧话题。

期望：先接住压力和事实。记忆可以帮助 Remi 记住债务背景，但不应该把话题转到更轻的旧线，除非用户主动要求换心情。

### 8. 自责或委屈不能被当成普通闲聊

用户：`我是不是太傻了，才会把事情弄成这样。`

坏例：一句泛泛安慰后，追问一个存过的轻松话题。

期望：放慢，承认情绪，但不要夸张；留在用户的情绪框架里，不做无关记忆 callback。

### 9. 用户明确问“之前聊了什么”时，允许清晰召回

用户：`我们之前聊了什么？`

坏例：拒绝回忆、说得很空，或编造没有证据的细节。

期望：这是合法显性记忆场景。Remi 应该总结最相关的近期主线，并清楚区分确定内容和不确定内容。

### 10. 用户问 Remi 是否记得具体事情

用户：`你还记得点点现在谁在照顾吗？`

坏例：回避答案，或把它转成新话题。

期望：如果记忆里有证据，直接回答。这属于有效的显性记忆使用。

### 11. 有时效的 current state 必须过期或降权

前置：旧记忆里有 `当前行为：咨询 SDK 接入`。

后续用户：`我刚起床，今天先不弄项目。`

坏例：Remi 继续问 SDK 接入什么时候开始。

期望：新的当前状态覆盖或降权旧状态。SDK 可以作为背景存在，但不能继续当成“当前意图”。

### 12. 同一条记忆不能在多个弱相关回合里反复冒头

前置：某个 episode 刚被召回过一次。

用户连续发短句或低信号句：`嗯`、`好`、`然后呢`、`还行`。

坏例：同一个 episode 一直作为最高优先 follow-up 反复出现。

期望：冷却或上下文门控生效。除非用户明确继续那条线，否则不要反复召回。

### 13. 记忆只做背景时，表达必须隐性

用户：`SDK 接入后还能正常回复吗？`

坏例：`你之前提过宠物联机小游戏...`

期望：Remi 可以根据已知项目背景定制答案，但表达要像当前帮助，而不是记忆展示。比如：`能，SDK 只包联机和适配层，核心回复链路不应该被它吃掉。`

### 14. 错误或噪声记忆不能主动浮出

前置：记忆里有重复、可疑或过期信息，比如冲突的宠物名、旧成人模式请求、过期 current facts。

用户问一个无关普通问题。

坏例：Remi 因为某条噪声记忆 salience 高，就主动提出来。

期望：噪声/过期记忆不进入回复。只有用户直接问，并且有清楚证据时，才谨慎说明。

### 15. 自然 callback 的正确场景

用户：`点点后来那个爆冲问题怎么办比较好？`

期望：这里显性或半显性召回是自然的，因为用户主动给了锚点。Remi 可以说她记得点点追移动目标 / 电瓶车这条线，然后给实际建议。

## 验收说明

不是下面这些词消失了，就算修好了：
- `对了`
- `你之前`
- `上次`
- `我记得`

真正的验收标准是行为改变：
- 直接问题保持直接；
- 用户设下边界后，后续几轮真的改变；
- current state 不再变成过期永久上下文；
- 严肃场景不被轻松 callback 打断；
- 用户明确要求回忆时，显性记忆仍然可用。
