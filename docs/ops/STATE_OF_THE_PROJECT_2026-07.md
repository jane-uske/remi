## 二、复杂度诊断（诚实的数字）

代码总量约 **11.5 万行**（不含测试），但真实使用面只有一小块：

| 区域 | 行数 | 真实使用状态 |
|---|---|---|
| iOS + watchOS | 88,274 | **几乎不用**（Live2D/全双工语音/HealthKit） |
| Web 前端 | 24,585 | 主要使用面 ✅ |
| 后端核心（server/brains/brain/memory/persona） | 33,987 | 核心价值 ✅ |
| voice（5 TTS + 3 STT + VAD/打断/全双工） | 6,603 | 只用 TTS 半边（MLX+Edge） |
| capabilities（视频/家庭记忆/回顾） | 3,947 | 基本不用 |
| desktop (Tauri) | 430+Rust | 不用 |
| 测试 | 31,376（165 文件，107 存量失败） | 维护负担 |
| 配置项/flag | 265 个 | 大部分从未改过默认值 |

**结论：这是一个按 20 人团队产品架构建造的系统，由 0.1 个人维护，服务 1 个用户。**
"维护不起、优化不起、改不动"不是能力问题，是维护面积与使用面积的比例失衡——每改一处核心，都拖着 6-7 万行不使用区域的测试、兼容与心智负担。

## 三、方向：三条路，推荐第一条

### 路线 A：收缩到「最小可爱 Remi」（推荐）

定义活跃区，其余全部冻结（不删代码——标记 FROZEN，不再改、不再测、坏了不修）：

**活跃区**（约 5 万行，聚焦她真正被使用的样子）
- Web 文本聊天全链路（gateway/session/pipeline/web）
- 记忆五层 + 防御评测体系（这两天刚修好的核心资产）
- 人格：remi pack + CANON + 离线人生 + 开场收场
- 语音输出：MLX TTS + Edge fallback
- 鉴权：Clerk 单账号路径

**冻结区**（约 6.5 万行）
- iOS / watchOS / desktop 三端
- STT 全家（语音输入）、全双工/VAD/打断/turn-taking 语音机器
- 视频生成、family-memory 微服务、邀请码/guest 系统
- nami / jp-coach 人格包（文件保留，不测试）

**配套动作**（一次性，约半天）
1. `npm run test:core`——只跑活跃区测试；107 个存量失败大多在冻结区，心理负担一次卸掉
2. CLAUDE.md 标注冻结区："不要为冻结区写代码/修测试，除非明确解冻"
3. flag 大扫除延后——冻结后它们自然不再碍事

### 路线 B：冻结现状，只修坏样本
零成本，但"改不动"的感觉会持续——复杂度没减，每次想动都要面对全部。

### 路线 C：推倒重写一个 500 行的小 Remi
诱人但不推荐：这两天验证过的资产（记忆时效、探针、canon、断层标记）搬迁成本高于收益。
