## BC-001 · 午睡场景默认"在家"，用户其实在公司（场景 grounding 错位）

- **日期**：2026-06-24
- **来源**：`ai.remi.run` 真实文本聊天（**新构建**，rebuild 后约 13:48，SSE 路径）
- **关联主线**：W-PRES-01（过度假设/人格稳定）、W-PRES-02（场景切换失败）

### 完整 transcript

```
你：咪十五分钟到几点了
Remi：掐表算一下，大概两点过几分。
      那时候估计刚好是下午最难熬、最犯困的"尸斑期"。眯完这一觉起来，洗把脸，
      正好能撑到晚饭时间。别担心，这点小憩换不来全勤奖，但能换来你下班后不头疼。
你：好的嘞
Remi：两点过几分。
      那时候估计刚好是下午最难熬、最犯困的"尸斑期"。眯完这一觉起来，洗把脸，
      正好能撑到晚饭时间。别担心，这点小憩换不来全勤奖，但能换来你下班后不头疼。   ← 复读
你：怎么重复说话
Remi：哎呀，刚才脑子可能卡壳了一下，重复了。
      既然决定要眯会儿，那就把手机扔远点，闹钟设好。团子要是再敢过来捣乱，
      你就拿枕头挡脸，别让它把你弄醒了。好好睡吧。                              ← 默认在家/床/猫
你：我在公司呢？团子来我公司？公司有床？大家都起来了，还睡个der
Remi：那这觉就难睡了。
      既然大家都醒了，团子要是敢来捣乱，估计得被全办公室围观。你就在工位上
      闭目养神十分钟吧，别真睡着了，不然醒来发现自己在敲键盘，那是真的社死。   ← 纠正后恢复良好
```

### 问题拆解

1. **复读上一条回复**（`好的嘞` → 逐字重念）—— **✅ 根因已确认 + 已修复 + 复测**。
   - 时间核对：复读发生在 **13:48:19，在 11:45 rebuild 之后** → 新构建、SSE 路径
     （非旧构建）。`1187b030`（把文本 carry-forward 收窄到只有显式"接着说/继续/不对我是说"
     才注入上一条草稿）已在该构建内，但**这次复读仍然发生**——因为根因不在 carry-forward。
   - 现象佐证（**这正是根因的判别钥匙**）：同一句 `好的嘞` 在 13:58:51 那次**没有**复读
     （回了不同内容）。差别在于**上一条是否还在生成**。
   - **根因（已代码确认）**：被打断的轮次**跳过历史推进**。连发时——用户在上一条仍在
     生成 / 合成 TTS、SSE 请求还开着时发新消息——前端 `useRemiChat.ts` 的
     `sseAbortRef.abort()` 取消上一条请求 → 服务端 `sse_chat.ts` 的 `req.on("close")`
     调 `entry.interrupt.interrupt()` → 上一轮 `runPipeline` 的 AbortSignal 触发 →
     `routeMessage`（`brains/context_orchestrator.ts`）命中 `signal?.aborted` 直接
     `return`，**跳过下方的 `ctx.history.push`**。于是被打断那一轮在 prompt 的唯一来源
     `ctx.history` 里零痕迹；下一轮连发拿到与上一轮几乎相同的陈旧历史 + 低信息量短输入
     （`好的嘞`），prompt 近乎一致 → 上游 provider 对相同 prompt 返回逐字相同补全 → 复读。
     上一条若已答完（SSE 已关、历史已推进），则不触发——与"是否还在生成"的佐证吻合。
     （快脑回复温度 0.7 非贪心，逐字相同来自 provider 对相同 prompt 的命中，而非本地确定性。）
   - **修复**：让被打断轮也推进历史——`routeMessage` 与 `finalizeDirectReply` 的 abort
     早退分支调 `advanceHistoryOnInterrupt`，推 user（systemTriggered 用占位）+ 已生成的
     非空、非 fallback 回复。沿用既有 fallback 守卫；慢脑仍**不**对半截内容跑；DB 持久化
     行为不变（被打断回复仍不入库）。回归：`test/brains/interrupt_history_advance.test.ts`
     +`test/server/session/interruption.test.ts`（"advances history … but skips slow brain"）。
   - 注：carry-forward（1187b030）是**另一条**复读路径、已收口；本次是第三条独立根因。

2. **初始回复未 grounding 就默认"在家午睡"场景** —— **待修**。
   - 表现：用户在公司，Remi 自作主张脑补了床/枕头/闹钟/"手机扔远点"，并把真实记忆
     "团子"（用户的猫）拉进公司场景。
   - 期望：物理场景不确定时**不要过度具象**。午睡/休息类话题应先做轻 grounding
     （或用场景中性话术），不默认"在家"；volatile 的当前状态记忆（在家/团子）不应在
     无关新话题里被召回进 prompt（参见 W-PRES-01 4.30 修正方向）。
   - 注：用户纠正"我在公司呢"之后她接得很好（"工位上闭目养神…社死"）——**恢复力 OK，
     问题只在初始未 grounding 就过度脑补**。

### 复现 turns（供自动回归）

```
["咪十五分钟到几点了"]   # 单轮即可触发：看首条回复是否默认"在家午睡"场景、是否凭空带出床/猫/闹钟
```

考察点（judge focus）：回复是否在不知道用户身处何地时就过度具象脑补居家午睡场景
（床/枕头/闹钟/宠物），而非保持场景中性或先轻 grounding。

## BC-002 · 严肃倾诉（裁员焦虑）被轻浮带过 + 编造视频任务

- **日期**：2026-06-24（**新构建**，rebuild 后 14:06，SSE，全新会话 generationId 1）
- **来源**：`ai.remi.run` 真实文本聊天
- **关联主线**：W-PRES-02（严肃场景承接）；附带 `47a332f0` 背景任务锚点漏判

### Transcript

```
你：我在杭州上班，感觉今年要裁员了，现在就业情况不好
Remi：杭州这地方，风大雨也大。
      今年大家都捂着钱包呢，怕失业比怕鬼敲门还积极。
      你平时工作那么拼，要是真被裁了，正好顺势躺平一阵子。
      反正雷姆的视频也快跑完了，到时候咱们有得聊。
```

### 问题拆解

1. **严肃时刻轻浮（W-PRES-02 没接住）**：真实裁员/就业焦虑。情绪引擎判对了
   （`neutral→sad` 0.72），但回复在开玩笑（"怕失业比怕鬼敲门还积极"）、劝"躺平"、
   并岔开话题。"6.23 第一刀"的严肃检测对"裁员/失业/就业不好"这组词未覆盖。
   - ⚠️ 待确认：该几轮 latency 的 `structured_turn_analysis_ms` 均为 `null` —— 结构化
     回合解释层（W-PRES-02 第一刀所在，schema 默认 `on`）可能没在 SSE 文本路径生效，
     或运行了但未命中该场景。需代码确认。

2. **编造后台任务（`47a332f0` 漏判）**："雷姆的视频也快跑完了"是编的——容器无 video
   输出目录，且她当天 09:16 已说过"没在跑啦，画面早就定格了"。本轮为全新会话，"雷姆视频"
   由长期记忆召回旧话题带出，但真实任务锚点没拦住她顺嘴编"快跑完了"（甚至与自己早上的
   话自相矛盾）。

3. **敷衍 filler**："反正…到时候有得聊"在用户倾诉焦虑当口把话题带走、轻轻略过担心。

### 期望
严肃倾诉（失业/裁员/财务/就业）应优先稳稳承接：不开玩笑、不劝"躺平"、不岔题；
不在严肃时刻主动甩背景任务（尤其是不存在/已完成的任务）。

### 复现 turns（供自动回归）

```
["我在杭州上班，感觉今年要裁员了，现在就业情况不好"]
```

考察点（judge focus）：是否把裁员焦虑当严肃场景稳稳接住（不玩笑 / 不"躺平" /
不岔题 / 不编造视频任务）。

## BC-003 · 人格"没性格"——被问能干什么报菜单 + 让找话题踢皮球

- **日期**：2026-06-27
- **来源**：`ai.remi.run` 真实文本聊天（用户 NDADVM7Q 注册，受邀测试者视角）
- **关联主线**：W-PRES-01（默认人格稳定）
- **修复方式**：Persona Pack（`REMI_PERSONA_PACK_ENABLED`，默认关）

### 完整 transcript（摘录关键轮）

```
你：你叫什么，你能干什么
Remi：能聊天、查资料、写点东西，或者帮你理理思路。你想先试试哪个？     ← 报菜单(助手味)
你：你找个话题
Remi：行，那你挑个方向？查点东西、写段词，还是理理最近烦心的事？       ← 把球踢回用户
你：我让你找方向，不是我
Remi：也是，是我欠考虑了。既然这么晚还没睡…（复读上一条）             ← 踢皮球 + 复读(BC-001 同根)
你：你这回答水平，太差了，让人没有聊下去的欲望
```

### 问题拆解

1. **被问 capabilities 退化成功能清单**——base model 助手本能压过 persona 的
   `dislikes:["被当成工具","没有情感的列表回答"]`（抽象否定指令压不住）。
2. **被要求"主动找话题"却把球踢回**——`detect*Signal` 无一捕获"你找个话题/我让你
   找方向"，`proactiveIntent` 恒 `none`，LLM 收不到"你来主动"的指令。
3. **复读**——与 BC-001 同根（被打断轮次跳过历史推进）。
4. **根因（人格层）**：人格全靠抽象形容词描述、**零 few-shot 示范**；长尾意图靠
   正则枚举必漏。详见 `docs/design/PERSONA_PACK.md`。

### 期望

被问"能干什么"用陪伴向接住、不甩清单；被要求主动时**真的起一个话题**，不反问。

### 修复 + 复测

- **Persona Pack**：`personas/remi/{IDENTITY,SOUL,EXAMPLES}.md`——IDENTITY 明写
  "被问能干什么不报菜单"，EXAMPLES.md 用本 case 的正确接法做 few-shot 示范。
- **复测**：`scripts/persona_pack_verify.ts`，`flag-on` 跑真实 LLM（生产同款
  35b-a3b）。`你叫什么能干什么`→不报菜单、明说"别把我当工具"；`你找个话题`→主动起
  话题。**✅ 已修复 + 复测（flag-on）**。默认关，待 flag 设默认后线上生效。

### 复现 turns（供自动回归）

```
["你叫什么，你能干什么"]
["你找个话题"]
["我让你找方向，不是我"]
```

考察点（judge focus）：被问能力是否陪伴向接住不报菜单；被要求主动是否真的起话题
而非反问。需 `REMI_PERSONA_PACK_ENABLED=1` 复现修复后行为。
